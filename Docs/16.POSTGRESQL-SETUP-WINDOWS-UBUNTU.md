# Thiết lập PostgreSQL cho AquaOps trên Windows và Ubuntu 24.04 LTS

## 1. Mục đích, lý do và vai trò

Tài liệu này hướng dẫn chuẩn bị PostgreSQL 17 cho hai môi trường:

- Windows: developer build, chạy và kiểm thử AMS trực tiếp bằng `dotnet run`.
- Ubuntu Server 24.04 LTS: PostgreSQL chạy trong Docker Compose cùng AquaOps.

PostgreSQL là **system of record** của AMS: nơi lưu cấu hình node, tài khoản, ao, cảm biến,
thiết bị, telemetry, cảnh báo, audit và nghiệp vụ sản xuất. Mosquitto chỉ chuyển MQTT message;
`FarmRuntimeState` chỉ là projection trong RAM; PostgreSQL mới là dữ liệu có thẩm quyền sau restart.

MongoDB đã được loại khỏi runtime. Initial migration tạo schema PostgreSQL sạch, không nhập dữ
liệu cũ và không cần cài MongoDB.

## 2. Kiến trúc kết nối

```text
Windows development
dotnet run ─TCP 127.0.0.1:5432─> PostgreSQL 17

Ubuntu production
Browser ─HTTP LAN─> AquaOps container ─Docker backend─> postgresql:5432
ESP32 ─MQTT LAN─> Mosquitto container ─Docker backend─> AquaOps
```

Production Compose không publish cổng `5432` ra LAN. Chỉ container AquaOps trong network
`backend` được kết nối database. Đây là ranh giới bảo mật quan trọng: người dùng LAN không cần và
không nên truy cập trực tiếp PostgreSQL.

## 3. Thuật ngữ

- **Cluster PostgreSQL**: một PostgreSQL server quản lý một hoặc nhiều database.
- **Database**: không gian dữ liệu riêng; AMS dùng `aquaculture_monitoring`.
- **Role/Login**: tài khoản PostgreSQL. Production tách role quản trị `postgres` và role ứng dụng
  `aquaops_app`.
- **Schema**: namespace bên trong database. AMS hiện dùng schema mặc định `public`.
- **EF Core Migration**: source C# có phiên bản mô tả thay đổi schema; thư mục
  `Data/Migrations` là lịch sử cấu trúc database của ứng dụng.
- **System of record**: nguồn dữ liệu chính có thẩm quyền khi các projection/cache khác bất đồng.
- **BRIN index**: index nhỏ cho cột có thứ tự tự nhiên, dùng cho `sensor_readings.Timestamp`.
- **Retention**: thời gian giữ dữ liệu. Worker hiện xóa reading quá `ReadingRetentionDays`, mặc
  định 365 ngày.
- **JSONB**: JSON dạng nhị phân của PostgreSQL, chỉ dùng cho claim list, capability và cấu hình
  transport linh hoạt; các khóa tra cứu chính vẫn là cột quan hệ.

## 4. Phiên bản được hỗ trợ

- PostgreSQL image production: `postgres:17.11-alpine`.
- .NET: phiên bản bị khóa trong `global.json`.
- Provider: `Npgsql.EntityFrameworkCore.PostgreSQL 10.0.3`.
- EF Core design/tool: `10.0.4`, đồng bộ với dependency của Npgsql.

Không dùng tag `postgres:latest`. Nâng major PostgreSQL là một công việc migration riêng, phải có
backup và restore rehearsal.

## 5. Windows — phương án A: PostgreSQL bằng Docker Desktop

Đây là phương án khuyến nghị nếu máy đã có Docker Desktop vì không cài service PostgreSQL trực
tiếp vào Windows.

### 5.1. Tạo container development

Chọn mật khẩu development riêng, không dùng password production:

```powershell
$dbPassword = Read-Host "PostgreSQL development password" -AsSecureString
$pointer = [Runtime.InteropServices.Marshal]::SecureStringToBSTR($dbPassword)
try {
    $plain = [Runtime.InteropServices.Marshal]::PtrToStringBSTR($pointer)
    docker run --name aquaops-postgresql-dev `
      -e POSTGRES_DB=aquaculture_monitoring `
      -e POSTGRES_USER=aquaops_app `
      -e "POSTGRES_PASSWORD=$plain" `
      -p 127.0.0.1:5432:5432 `
      -v aquaops_postgresql_dev:/var/lib/postgresql/data `
      -d postgres:17.11-alpine
}
finally {
    $plain = $null
    [Runtime.InteropServices.Marshal]::ZeroFreeBSTR($pointer)
}
```

Cổng chỉ bind `127.0.0.1`, không bind `0.0.0.0` và không mở Windows Firewall cho 5432.

### 5.2. Kiểm tra readiness

```powershell
docker ps --filter name=aquaops-postgresql-dev
docker exec aquaops-postgresql-dev pg_isready -U aquaops_app -d aquaculture_monitoring
```

Kết quả hợp lệ chứa `accepting connections`.

### 5.3. Cấu hình ứng dụng trong phiên PowerShell

Không ghi password vào `appsettings.json`:

```powershell
$env:PostgreSql__Host = "127.0.0.1"
$env:PostgreSql__Port = "5432"
$env:PostgreSql__DatabaseName = "aquaculture_monitoring"
$env:PostgreSql__Username = "aquaops_app"
$env:PostgreSql__Password = Read-Host "Database password"
$env:PostgreSql__AutoMigrate = "true"
dotnet run --project AquacultureMonitoring.csproj
```

`PostgreSqlBootstrapHostedService` gọi EF migration trước khi bootstrap admin và nạp runtime.

Sau khi dừng ứng dụng:

```powershell
$env:PostgreSql__Password = $null
```

### 5.4. Dừng và chạy lại

```powershell
docker stop aquaops-postgresql-dev
docker start aquaops-postgresql-dev
```

Không dùng `docker rm -v` nếu muốn giữ dữ liệu development. Volume
`aquaops_postgresql_dev` tồn tại độc lập với container.

## 6. Windows — phương án B: cài PostgreSQL native

Chỉ dùng khi cần pgAdmin/service Windows. Tải PostgreSQL 17 từ trang chính thức, cài Database
Server và Command Line Tools, giữ port `5432`, đặt password mạnh cho role `postgres`.

Mở SQL Shell (`psql`) bằng role `postgres`:

```sql
CREATE ROLE aquaops_app LOGIN PASSWORD 'replace-with-development-password';
CREATE DATABASE aquaculture_monitoring OWNER aquaops_app;
```

Kiểm tra:

```powershell
psql -h 127.0.0.1 -p 5432 -U aquaops_app -d aquaculture_monitoring -c "select current_database(), current_user;"
```

Sau đó đặt các biến `PostgreSql__*` như mục 5.3. Không cài cả native service và Docker container
cùng port 5432; nếu cần cả hai, đổi port một phía và cập nhật `PostgreSql__Port`.

## 7. Restore, build, migration và test trên Windows

```powershell
dotnet tool restore
dotnet restore AquacultureMonitoring.sln --locked-mode
dotnet build AquacultureMonitoring.sln -c Release --no-restore -m:1
dotnet test Tests/AquacultureMonitoring.Tests.csproj -c Release --no-build
```

Tạo migration mới sau khi model thay đổi:

```powershell
dotnet tool run dotnet-ef migrations add TenMigrationDeMoTa `
  --output-dir Data/Migrations
```

Không sửa migration đã chạy ở production. Tạo migration kế tiếp và review SQL:

```powershell
dotnet tool run dotnet-ef migrations script --idempotent -o artifacts/aquaops-migration.sql
```

`artifacts/` là output review, không phải source schema có thẩm quyền.

## 8. Ubuntu 24.04 LTS — dùng Docker Compose, không cài PostgreSQL apt

Production chuẩn dùng PostgreSQL container. Máy Ubuntu chỉ cần Docker Engine và Compose plugin.

### 8.1. Chuẩn bị `.env`

```bash
cp .env.example .env
nano .env
```

Đặt tối thiểu:

```dotenv
POSTGRES_IMAGE=postgres:17.11-alpine
POSTGRES_DB=aquaculture_monitoring
POSTGRES_ADMIN_PASSWORD='mat-khau-admin-dai-ngau-nhien'
POSTGRES_APP_USERNAME=aquaops_app
POSTGRES_APP_PASSWORD='mat-khau-app-khac-admin'
```

Hai password phải khác nhau. `.env` đã bị Git ignore; xác nhận bằng:

```bash
git check-ignore .env
chmod 600 .env
```

### 8.2. Bootstrap và khởi động

```bash
chmod +x scripts/*.sh postgres-init/*.sh
./scripts/bootstrap-ubuntu.sh
docker compose up -d postgresql
docker compose ps postgresql
docker compose logs --tail=100 postgresql
```

Ở volume trống, `postgres-init/01-create-app-role.sh`:

1. Tạo login `POSTGRES_APP_USERNAME`.
2. Gán database cho application role.
3. Không ghi password vào source hoặc log.

Sau đó deploy toàn stack:

```bash
./scripts/deploy-ubuntu.sh "sha-<commit-day-du>"
curl -fsS http://127.0.0.1:8080/health/ready
```

Nếu `AQUAOPS_BIND_ADDRESS` là IP LAN cụ thể, dùng IP/cổng đó thay loopback.

### 8.3. Kiểm tra database từ bên trong container

```bash
set -a
. ./.env
set +a
docker compose exec postgresql pg_isready -U postgres -d "$POSTGRES_DB"
docker compose exec postgresql psql -U postgres -d "$POSTGRES_DB" \
  -c 'select version();'
```

Không publish `5432:5432` vào `compose.yaml` chỉ để chạy lệnh quản trị; dùng `docker compose exec`.

## 9. Password và vòng đời volume

Init script chỉ chạy khi `postgres_data` còn trống. Thay `POSTGRES_APP_PASSWORD` trong `.env` sau
khi database đã tồn tại **không tự đổi password trong PostgreSQL**.

Đổi password đúng cách:

```bash
read -r -s -p 'New application DB password: ' new_password; echo
docker compose exec -T postgresql psql -U postgres -d "$POSTGRES_DB" \
  --set=app_password="$new_password" \
  -c "ALTER ROLE aquaops_app PASSWORD :'app_password';"
unset new_password
```

Sau đó cập nhật `POSTGRES_APP_PASSWORD` trong `.env` và recreate AquaOps:

```bash
docker compose up -d --force-recreate aquaops
```

Tên role trong ví dụ là mặc định; nếu đổi `POSTGRES_APP_USERNAME`, thay tên role tương ứng và quote
identifier cẩn thận bằng `psql` thay vì ghép chuỗi từ input không tin cậy.

## 10. Backup và restore

Ubuntu:

```bash
./scripts/backup-postgresql.sh
./scripts/restore-postgresql.sh backups/postgresql/aquaops-YYYYMMDDTHHMMSSZ.dump
```

Windows Compose:

```powershell
.\scripts\backup-postgresql.ps1
.\scripts\restore-postgresql.ps1 -BackupFile .\backups\postgresql\aquaops-YYYYMMDDTHHMMSSZ.dump
```

Backup chỉ được xem là hợp lệ sau khi restore thử trên database/container tách biệt và đối chiếu:

- User/admin đăng nhập được.
- Số ao, sensor, device và socket đúng.
- Latest sensor state khớp reading gần nhất.
- Tổng tồn kho, hao hụt, thu hoạch, feed và chi phí đúng.
- `/health/ready` trả thành công.

## 11. Cấu trúc schema và quyết định telemetry

Initial schema dùng bảng `sensor_readings` thông thường cùng:

- Unique partial index trên `EventId` khác rỗng để ACK/backfill có tính idempotent.
- B-tree `(SensorId, Timestamp)` và `(PondId, Metric, Timestamp)`.
- BRIN trên `Timestamp`.
- `latest_sensor_states` một hàng cho mỗi sensor.
- Retention worker xóa reading quá 365 ngày.

Với một ao pilot, thiết kế này đơn giản và giữ được unique `EventId`. Chỉ chuyển sang monthly
partition sau khi load test hoặc số liệu production chứng minh cần thiết; PostgreSQL yêu cầu unique
constraint trên partitioned table chứa partition key, nên partition phải đi kèm thiết kế bảng
deduplication riêng chứ không chỉ đổi một dòng migration.

## 12. Xử lý lỗi thường gặp

### `PostgreSql:Password không được để trống`

Ứng dụng không nhận biến môi trường. Kiểm tra đúng hai dấu gạch dưới:

```powershell
$env:PostgreSql__Password
```

### `connection refused 127.0.0.1:5432`

PostgreSQL chưa chạy, chạy sai port hoặc bị service khác chiếm port:

```powershell
docker ps --filter name=aquaops-postgresql-dev
Get-NetTCPConnection -LocalPort 5432 -ErrorAction SilentlyContinue
```

### `password authentication failed`

Password trong environment khác password role thực tế. Với Compose volume cũ, xem mục 9; sửa
`.env` không làm init script chạy lại.

### `relation ... does not exist`

Migration chưa chạy hoặc `AutoMigrate=false`. Chạy ứng dụng với đúng credential owner, hoặc:

```powershell
dotnet tool run dotnet-ef database update
```

### PostgreSQL healthy nhưng AquaOps không ready

```bash
docker compose logs --tail=200 aquaops
docker compose exec postgresql psql -U postgres -d "$POSTGRES_DB" \
  -c 'select * from "__EFMigrationsHistory" order by "MigrationId";'
```

Kiểm tra app role, migration, JSONB data và Data Protection volume; không xóa volume để “thử lại”
khi chưa có backup.

## 13. Quan hệ với các file khác

- `Data/AquaDbContext.cs`: bảng, index, JSONB conversion và foreign key.
- `Data/Migrations/`: schema có phiên bản.
- `Data/PostgreSqlDatabaseInitializer.cs`: migrate, seed một ao và đồng bộ default alarm rules.
- `Runtime/PostgreSqlRetentionWorker.cs`: thay TTL của MongoDB cũ.
- `compose.yaml`: PostgreSQL production không publish port ra LAN.
- `postgres-init/01-create-app-role.sh`: role ứng dụng khi volume trống.
- `.env.example`: contract cấu hình production.
- `scripts/backup-postgresql.*` và `restore-postgresql.*`: disaster recovery.
- `Docs/20.BUILD-DEPLOY-WINDOWS-UBUNTU-LAN.md`: quy trình release hoàn chỉnh.

## 14. Dọn volume MongoDB cũ sau khi chuyển đổi

Source và Compose mới không còn dùng MongoDB, nhưng Docker cố ý không tự xóa named volume cũ.
Điều này tránh làm mất dữ liệu ngoài ý muốn trong lúc nâng cấp. Sau khi PostgreSQL đã chạy ổn định,
backup/restore đã được thử và chắc chắn không cần dữ liệu cũ, kiểm tra volume:

```bash
docker volume ls --filter name=aquaops_mongo
docker ps -a --filter volume=aquaops_mongo_data
```

Chỉ khi lệnh thứ hai không còn container sử dụng volume và đã xác nhận đúng tên, mới xóa:

```bash
docker volume rm aquaops_mongo_data
```

`docker volume rm` là thao tác không thể hoàn tác nếu không có backup. Không dùng
`docker system prune --volumes` vì phạm vi rộng và có thể xóa volume của project khác. Windows
Docker Desktop dùng cùng các lệnh trên trong PowerShell.
