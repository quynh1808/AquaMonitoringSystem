# Thiết lập PostgreSQL cho AquaOps trên Windows và Ubuntu 24.04 LTS

## 1. Mục đích, lý do và vai trò

Tài liệu này hướng dẫn chuẩn bị PostgreSQL 17 cho hai môi trường:

- Windows: developer build, chạy và kiểm thử AMS trực tiếp bằng `dotnet run`.
- Ubuntu Server 24.04 LTS: PostgreSQL chạy trong Docker Compose cùng AquaOps.

PostgreSQL là **system of record** của AMS: nơi lưu cấu hình node, tài khoản, ao, cảm biến,
thiết bị, telemetry, cảnh báo, audit và nghiệp vụ sản xuất. Mosquitto chỉ chuyển MQTT message;
`FarmRuntimeState` chỉ là projection trong RAM; PostgreSQL mới là dữ liệu có thẩm quyền sau restart.

MongoDB đã được loại khỏi runtime. Initial migration tạo schema PostgreSQL sạch, không nhập dữ
liệu cũ và không cần cài MongoDB.

## 2. Kiến trúc kết nối

```text
Windows development
dotnet run ─TCP 127.0.0.1:5432─> PostgreSQL 17

Ubuntu production
Browser ─HTTP LAN─> AquaOps container ─Docker backend─> postgresql:5432
ESP32 ─MQTT LAN─> Mosquitto container ─Docker backend─> AquaOps
```

> **Quan trọng:** khối trên là sơ đồ luồng kết nối, không phải câu lệnh PowerShell. Không chạy
> `dotnet run ─TCP 127.0.0.1:5432`. Câu lệnh thực tế chỉ là
> `dotnet run --project AquacultureMonitoring.csproj` sau khi đã cấu hình các biến
> `PostgreSql__*`.

Production Compose không publish cổng `5432` ra LAN. Chỉ container AquaOps trong network
`backend` được kết nối database. Đây là ranh giới bảo mật quan trọng: người dùng LAN không cần và
không nên truy cập trực tiếp PostgreSQL.

## 3. Thuật ngữ

- **Cluster PostgreSQL**: một PostgreSQL server quản lý một hoặc nhiều database.
- **Database**: không gian dữ liệu riêng; AMS dùng `aquaculture_monitoring`.
- **Role/Login**: tài khoản PostgreSQL. Production tách role quản trị `postgres` và role ứng dụng
  `aquaops_app`.
- **Schema**: namespace bên trong database. AMS hiện dùng schema mặc định `public`.
- **EF Core Migration**: source C# có phiên bản mô tả thay đổi schema; thư mục
  `Data/Migrations` là lịch sử cấu trúc database của ứng dụng.
- **System of record**: nguồn dữ liệu chính có thẩm quyền khi các projection/cache khác bất đồng.
- **BRIN index**: index nhỏ cho cột có thứ tự tự nhiên, dùng cho `sensor_readings.Timestamp`.
- **Retention**: thời gian giữ dữ liệu. Worker hiện xóa reading quá `ReadingRetentionDays`, mặc
  định 365 ngày.
- **JSONB**: JSON dạng nhị phân của PostgreSQL, chỉ dùng cho claim list, capability và cấu hình
  transport linh hoạt; các khóa tra cứu chính vẫn là cột quan hệ.

## 4. Phiên bản được hỗ trợ

- Windows native: **PostgreSQL 17.11, Windows x86-64**.
- PostgreSQL image production: `postgres:17.11-alpine`.
- .NET: phiên bản bị khóa trong `global.json`.
- Provider: `Npgsql.EntityFrameworkCore.PostgreSQL 10.0.3`.
- EF Core design/tool: `10.0.4`, đồng bộ với dependency của Npgsql.

Không dùng tag `postgres:latest`. Nâng major PostgreSQL là một công việc migration riêng, phải có
backup và restore rehearsal.

Không chọn PostgreSQL 18 chỉ vì đây là major mới hơn. Development và production nên cùng major 17
để migration, kiểu dữ liệu, công cụ backup/restore và hành vi runtime được kiểm tra nhất quán.

## 5. Windows — phương án A: PostgreSQL bằng Docker Desktop

Đây là phương án khuyến nghị nếu máy đã có Docker Desktop vì không cài service PostgreSQL trực
tiếp vào Windows.

### 5.1. Tạo container development

Chọn mật khẩu development riêng, không dùng password production:

```powershell
$dbPassword = Read-Host "PostgreSQL development password" -AsSecureString
$pointer = [Runtime.InteropServices.Marshal]::SecureStringToBSTR($dbPassword)
try {
    $plain = [Runtime.InteropServices.Marshal]::PtrToStringBSTR($pointer)
    docker run --name aquaops-postgresql-dev `
      -e POSTGRES_DB=aquaculture_monitoring `
      -e POSTGRES_USER=aquaops_app `
      -e "POSTGRES_PASSWORD=$plain" `
      -p 127.0.0.1:5432:5432 `
      -v aquaops_postgresql_dev:/var/lib/postgresql/data `
      -d postgres:17.11-alpine
}
finally {
    $plain = $null
    [Runtime.InteropServices.Marshal]::ZeroFreeBSTR($pointer)
}
```

Cổng chỉ bind `127.0.0.1`, không bind `0.0.0.0` và không mở Windows Firewall cho 5432.

### 5.2. Kiểm tra readiness

```powershell
docker ps --filter name=aquaops-postgresql-dev
docker exec aquaops-postgresql-dev pg_isready -U aquaops_app -d aquaculture_monitoring
```

Kết quả hợp lệ chứa `accepting connections`.

### 5.3. Cấu hình ứng dụng trong phiên PowerShell

Không ghi password vào `appsettings.json`:

```powershell
$env:PostgreSql__Host = "127.0.0.1"
$env:PostgreSql__Port = "5432"
$env:PostgreSql__DatabaseName = "aquaculture_monitoring"
$env:PostgreSql__Username = "aquaops_app"
$databaseSecret = Read-Host "Password của aquaops_app" -AsSecureString
$databaseCredential = [PSCredential]::new("aquaops_app", $databaseSecret)
$env:PostgreSql__Password = $databaseCredential.GetNetworkCredential().Password
$databaseCredential = $null
$databaseSecret = $null
$env:PostgreSql__AutoMigrate = "true"
dotnet run --project AquacultureMonitoring.csproj
```

`PostgreSqlBootstrapHostedService` gọi EF migration trước khi bootstrap admin và nạp runtime.

Sau khi dừng ứng dụng:

```powershell
$env:PostgreSql__Password = $null
```

### 5.4. Dừng và chạy lại

```powershell
docker stop aquaops-postgresql-dev
docker start aquaops-postgresql-dev
```

Không dùng `docker rm -v` nếu muốn giữ dữ liệu development. Volume
`aquaops_postgresql_dev` tồn tại độc lập với container.

## 6. Windows — phương án B: cài PostgreSQL native

Chỉ dùng khi cần pgAdmin hoặc muốn PostgreSQL chạy như Windows Service mà không phụ thuộc Docker
Desktop.

### 6.1. Chọn phiên bản và thành phần trong installer

Tải **PostgreSQL 17.11 Windows x86-64** từ
[trang Windows Download chính thức của PostgreSQL](https://www.postgresql.org/download/windows/).
Trong EDB installer, giữ các thành phần:

- **PostgreSQL Server**: database engine bắt buộc.
- **Command Line Tools**: cung cấp `psql`, `pg_dump`, `pg_restore` và `pg_isready`.
- **pgAdmin 4**: giao diện đồ họa, không bắt buộc nhưng nên giữ cho máy development.
- **Stack Builder**: không cần cho AquaOps.

Các lựa chọn cài đặt khuyến nghị:

1. Installation directory: giữ mặc định `C:\Program Files\PostgreSQL\17`.
2. Data directory: giữ mặc định nếu ổ đĩa hệ thống còn đủ chỗ.
3. Password: đặt mật khẩu mạnh cho superuser `postgres` và lưu trong password manager. Đây không
   phải password đăng nhập AquaOps.
4. Port: `5432`.
5. Locale: `Default locale`, trừ khi có yêu cầu vận hành riêng.
6. Xác nhận summary và hoàn tất installer.

Ở màn hình cuối, bỏ chọn **Launch Stack Builder at exit**. Nếu Stack Builder đã mở và báo phải chọn
ít nhất một category khi nhấn Next, hãy nhấn **Cancel** hoặc đóng cửa sổ. Thoát Stack Builder không
gỡ PostgreSQL. AquaOps dùng Npgsql từ NuGet, không cần database driver, PostGIS, replication tool
hay package bổ sung từ Stack Builder.

### 6.2. Kiểm tra Windows Service và cổng 5432

Mở PowerShell. Lệnh sau không cần quyền Administrator để xem trạng thái:

```powershell
Get-Service postgresql*
Test-NetConnection 127.0.0.1 -Port 5432
```

Kết quả mong đợi là service có `Status` bằng `Running` và `TcpTestSucceeded` bằng `True`.

Nếu service tồn tại nhưng đang dừng, mở PowerShell bằng **Run as administrator** rồi chạy:

```powershell
Get-Service postgresql* | Start-Service
```

Nếu `Get-Service postgresql*` không trả kết quả, PostgreSQL Server chưa được cài thành Windows
Service. Chạy lại installer và chắc chắn đã chọn PostgreSQL Server. Nếu cổng không mở, xem log tại
data directory hoặc kiểm tra có chương trình khác giữ cổng:

```powershell
Get-NetTCPConnection -LocalPort 5432 -ErrorAction SilentlyContinue
```

Không chạy đồng thời PostgreSQL native và container development trên cùng `127.0.0.1:5432`.

### 6.3. Xác nhận công cụ `psql`

Installer có thể chưa thêm `psql` vào `PATH`. Dùng đường dẫn đầy đủ để tránh nhầm phiên bản:

```powershell
& "C:\Program Files\PostgreSQL\17\bin\psql.exe" --version
```

Kết quả phải bắt đầu bằng `psql (PostgreSQL) 17`. Sau đó đăng nhập bằng superuser đã tạo khi cài:

```powershell
& "C:\Program Files\PostgreSQL\17\bin\psql.exe" `
  -h 127.0.0.1 -p 5432 -U postgres -d postgres
```

Nhập password của `postgres` khi được hỏi. Password không hiển thị ký tự khi gõ; đây là hành vi
bình thường.

### 6.4. Tạo application role và database bằng `psql`

Trong prompt `postgres=#`, thay placeholder bằng một password development riêng rồi chạy từng câu:

```sql
CREATE ROLE aquaops_app LOGIN PASSWORD 'replace-with-development-password';
CREATE DATABASE aquaculture_monitoring OWNER aquaops_app;
\du
\l
\q
```

`postgres` là tài khoản quản trị database; `aquaops_app` là tài khoản ít quyền hơn mà ứng dụng dùng.
Không cấu hình AquaOps chạy bằng `postgres`.

Nếu role hoặc database đã tồn tại, không tạo bản trùng. Đăng nhập lại bằng `postgres`, kiểm tra bằng
`\du` và `\l`; nếu cần đồng bộ password/owner trong môi trường development:

```sql
ALTER ROLE aquaops_app PASSWORD 'replace-with-development-password';
ALTER DATABASE aquaculture_monitoring OWNER TO aquaops_app;
```

### 6.5. Cách tương đương bằng pgAdmin 4

Nếu không muốn dùng SQL Shell:

1. Mở pgAdmin 4, mở `Servers` → `PostgreSQL 17` và nhập password `postgres`.
2. Chuột phải `Login/Group Roles` → `Create` → `Login/Group Role`.
3. Tab **General** đặt Name là `aquaops_app`.
4. Tab **Definition** đặt password development.
5. Tab **Privileges** bật `Can login?`; không bật Superuser, Create roles hoặc Replication.
6. Chuột phải `Databases` → `Create` → `Database`.
7. Đặt Database là `aquaculture_monitoring`, Owner là `aquaops_app`, rồi Save.

### 6.6. Kiểm tra kết nối bằng application role

Trong PowerShell:

```powershell
& "C:\Program Files\PostgreSQL\17\bin\psql.exe" `
  -h 127.0.0.1 -p 5432 -U aquaops_app -d aquaculture_monitoring `
  -c "select current_database(), current_user, version();"
```

Kết quả hợp lệ có `aquaculture_monitoring` và `aquaops_app`. Nếu bước này thất bại thì chưa chạy
`dotnet run`; sửa kết nối database trước theo mục 12.

`appsettings.json` cố ý để password trống. Đặt các biến sau trong **cùng cửa sổ PowerShell** sẽ chạy

### 7.4. Chạy ứng dụng và để EF tạo schema

Vẫn trong PowerShell đã đặt `PostgreSql__*`:

```powershell
dotnet run --project AquacultureMonitoring.csproj
```

Không thêm ký tự mũi tên hoặc chuỗi `TCP 127.0.0.1:5432` vào lệnh. Lần đầu khởi động,
`PostgreSqlBootstrapHostedService` sẽ:

1. Kết nối bằng `aquaops_app`.
2. Áp dụng migration trong `Data/Migrations` vì `AutoMigrate=true`.
3. Tạo baseline một ao và không tạo sensor/device mặc định.
4. Tạo tài khoản admin bootstrap khi bảng `users` đang rỗng.
5. Nạp dữ liệu cần thiết vào `FarmRuntimeState`.

URL development được định nghĩa trong `Properties/launchSettings.json` là
`http://localhost:5080`. Giữ cửa sổ `dotnet run` mở, rồi dùng PowerShell thứ hai để kiểm tra:

```powershell
Invoke-WebRequest -UseBasicParsing http://localhost:5080/health/live
Invoke-WebRequest -UseBasicParsing http://localhost:5080/health/ready
```

Cả hai phải trả `StatusCode 200`; readiness chỉ thành công khi PostgreSQL truy cập được.

## 9. Password và vòng đời volume

Init script chỉ chạy khi `postgres_data` còn trống. Thay `POSTGRES_APP_PASSWORD` trong `.env` sau
khi database đã tồn tại **không tự đổi password trong PostgreSQL**.

Đổi password đúng cách:

```bash
read -r -s -p 'New application DB password: ' new_password; echo
docker compose exec -T postgresql psql -U postgres -d "$POSTGRES_DB" \
  --set=app_password="$new_password" \
  -c "ALTER ROLE aquaops_app PASSWORD :'app_password';"
unset new_password
```

Sau đó cập nhật `POSTGRES_APP_PASSWORD` trong `.env` và recreate AquaOps:

```bash
docker compose up -d --force-recreate aquaops
```

Tên role trong ví dụ là mặc định; nếu đổi `POSTGRES_APP_USERNAME`, thay tên role tương ứng và quote
identifier cẩn thận bằng `psql` thay vì ghép chuỗi từ input không tin cậy.

## 10. Backup và restore

Ubuntu:

```bash
./scripts/backup-postgresql.sh
./scripts/restore-postgresql.sh backups/postgresql/aquaops-YYYYMMDDTHHMMSSZ.dump
```

Windows Compose:

```powershell
.\scripts\backup-postgresql.ps1
.\scripts\restore-postgresql.ps1 -BackupFile .\backups\postgresql\aquaops-YYYYMMDDTHHMMSSZ.dump
```

Backup chỉ được xem là hợp lệ sau khi restore thử trên database/container tách biệt và đối chiếu:

- User/admin đăng nhập được.
- Số ao, sensor, device và socket đúng.
- Latest sensor state khớp reading gần nhất.
- Tổng tồn kho, hao hụt, thu hoạch, feed và chi phí đúng.
- `/health/ready` trả thành công.

## 11. Cấu trúc schema và quyết định telemetry

Initial schema dùng bảng `sensor_readings` thông thường cùng:

- Unique partial index trên `EventId` khác rỗng để ACK/backfill có tính idempotent.
- B-tree `(SensorId, Timestamp)` và `(PondId, Metric, Timestamp)`.
- BRIN trên `Timestamp`.
- `latest_sensor_states` một hàng cho mỗi sensor.
- Retention worker xóa reading quá 365 ngày.

Với một ao pilot, thiết kế này đơn giản và giữ được unique `EventId`. Chỉ chuyển sang monthly
partition sau khi load test hoặc số liệu production chứng minh cần thiết; PostgreSQL yêu cầu unique
constraint trên partitioned table chứa partition key, nên partition phải đi kèm thiết kế bảng
deduplication riêng chứ không chỉ đổi một dòng migration.

## 12. Xử lý lỗi thường gặp

### PowerShell báo lỗi tại ký tự `─` hoặc `>`

Bạn đã sao chép sơ đồ `dotnet run ─TCP ...─> PostgreSQL`, không phải câu lệnh. Quay lại repository,
đặt các biến ở mục 7.2 rồi chỉ chạy:

```powershell
dotnet run --project AquacultureMonitoring.csproj
```

### Stack Builder báo phải chọn ít nhất một category

Nhấn `Cancel` hoặc đóng Stack Builder. Đây là trình cài add-on tùy chọn, không phải bước tạo
database. Không chọn ngẫu nhiên một driver/add-on để vượt qua màn hình này.

### PowerShell báo `psql is not recognized`

Gọi executable bằng đường dẫn đầy đủ:

```powershell
& "C:\Program Files\PostgreSQL\17\bin\psql.exe" --version
```

Nếu file không tồn tại, chạy lại installer và thêm **Command Line Tools**.

### `PostgreSql:Password không được để trống`

Ứng dụng không nhận biến môi trường. Kiểm tra đúng hai dấu gạch dưới:

```powershell
$env:PostgreSql__Password
```

### `connection refused 127.0.0.1:5432`

PostgreSQL chưa chạy, chạy sai port hoặc bị service khác chiếm port:

```powershell
docker ps --filter name=aquaops-postgresql-dev
Get-Service postgresql*
Test-NetConnection 127.0.0.1 -Port 5432
Get-NetTCPConnection -LocalPort 5432 -ErrorAction SilentlyContinue
```

Nếu dùng native, service `postgresql-x64-17` phải Running. Nếu dùng Docker Desktop, container
`aquaops-postgresql-dev` phải Up. Chỉ một trong hai được bind cổng 5432.

### `password authentication failed`

Password trong environment khác password role thực tế. Với Compose volume cũ, xem mục 9; sửa
`.env` không làm init script chạy lại.

Với Windows native, đăng nhập bằng `postgres` và đặt lại password development:

```sql
ALTER ROLE aquaops_app PASSWORD 'new-development-password';
```

Sau đó nhập chính password mới khi thiết lập `$env:PostgreSql__Password`.

### `role "aquaops_app" already exists` hoặc `database ... already exists`

Đây không phải lỗi cài server. Role/database đã được tạo ở lần trước. Dùng `\du` và `\l` trong
`psql` để xác nhận, sau đó dùng `ALTER ROLE`/`ALTER DATABASE ... OWNER TO ...` như mục 6.4 thay vì
tạo lại.

### `database "aquaculture_monitoring" does not exist`

Bạn mới cài PostgreSQL Server nhưng chưa tạo database của ứng dụng. Đăng nhập database `postgres`
bằng superuser rồi chạy phần `CREATE DATABASE` tại mục 6.4.

### `permission denied for schema public`

Database không thuộc `aquaops_app`, thường xảy ra khi database được tạo bằng owner mặc định. Đăng
nhập bằng `postgres` và sửa:

```sql
ALTER DATABASE aquaculture_monitoring OWNER TO aquaops_app;
\connect aquaculture_monitoring
GRANT ALL ON SCHEMA public TO aquaops_app;
```

### `relation ... does not exist`

Migration chưa chạy hoặc `AutoMigrate=false`. Với quy trình hiện tại, đặt
`PostgreSql__AutoMigrate=true` và chạy ứng dụng bằng đúng credential owner; bootstrap sẽ áp dụng
migration trước khi khởi động worker. `AquaDbContextDesignFactory` chủ yếu phục vụ tạo/review
migration và dùng connection placeholder, vì vậy không dùng `dotnet-ef database update` như một
lệnh vận hành production mặc định.

### `/health/live` đạt nhưng `/health/ready` thất bại trên Windows

Ứng dụng web đang chạy nhưng health check PostgreSQL lỗi. Xem console của `dotnet run`, sau đó kiểm
tra độc lập bằng application role theo mục 6.6. Ba nguyên nhân thường gặp là service dừng, password
không khớp hoặc database/owner chưa được tạo đúng.

### PostgreSQL healthy nhưng AquaOps không ready

```bash
docker compose logs --tail=200 aquaops
docker compose exec postgresql psql -U postgres -d "$POSTGRES_DB" \
  -c 'select * from "__EFMigrationsHistory" order by "MigrationId";'
```

Kiểm tra app role, migration, JSONB data và Data Protection volume; không xóa volume để “thử lại”
khi chưa có backup.

## 14. Dọn volume MongoDB cũ sau khi chuyển đổi

Source và Compose mới không còn dùng MongoDB, nhưng Docker cố ý không tự xóa named volume cũ.
Điều này tránh làm mất dữ liệu ngoài ý muốn trong lúc nâng cấp. Sau khi PostgreSQL đã chạy ổn định,
backup/restore đã được thử và chắc chắn không cần dữ liệu cũ, kiểm tra volume:

```bash
docker volume ls --filter name=aquaops_mongo
docker ps -a --filter volume=aquaops_mongo_data
```

Chỉ khi lệnh thứ hai không còn container sử dụng volume và đã xác nhận đúng tên, mới xóa:

```bash
docker volume rm aquaops_mongo_data
```

`docker volume rm` là thao tác không thể hoàn tác nếu không có backup. Không dùng
`docker system prune --volumes` vì phạm vi rộng và có thể xóa volume của project khác. Windows
Docker Desktop dùng cùng các lệnh trên trong PowerShell.
