# Bản đồ toàn bộ source code AquaOps

## 1. Mục đích, lý do và phạm vi

Đây là tài liệu nhập môn trung tâm cho toàn bộ repository AquaOps. Mục tiêu là một người mới có thể trả lời được bốn câu hỏi trước khi sửa code:

1. File hoặc thư mục này tồn tại để làm gì?
2. Vì sao trách nhiệm đó không đặt ở nơi khác?
3. Nó nhận dữ liệu từ đâu và ảnh hưởng thành phần nào?
4. Khi sửa nó cần đọc, build và kiểm tra những gì?

Tài liệu bao phủ source được lưu trong Git, từ web Blazor, service nghiệp vụ, MongoDB, pipeline MQTT/Modbus, firmware ESP32, script vận hành đến CI/CD. Các thư mục sinh tự động như **bin**, **obj**, dữ liệu MongoDB volume và key runtime không phải source nên chỉ được giải thích vai trò, không liệt kê từng file nhị phân.

Thuật ngữ chuyên môn được giải thích tại [02.TECHNICAL-GLOSSARY.md](02.TECHNICAL-GLOSSARY.md). Tài liệu của từng module tiếp tục giải thích các từ quan trọng ngay tại nơi sử dụng.

### 1.1 Ý nghĩa số thứ tự của tài liệu

Tất cả file trong thư mục **Docs** dùng tiền tố hai chữ số từ **01.** đến **23.**. Số nhỏ hơn có mức ưu tiên đọc trước:

- **01–03**: nhập môn repository, từ điển và chỉ mục tìm file.
- **04–06**: yêu cầu giao diện, thiết kế và ranh giới phân quyền.
- **07–10**: các mốc đã triển khai, commissioning động và nghiệp vụ vụ nuôi.
- **11–15**: chuyển mode, tích hợp hardware, provisioning, tham khảo legacy và security.
- **16–19**: build, Git, phát hành container và deploy Windows–Ubuntu.
- **20–23**: xử lý sự cố và các báo cáo validation lịch sử.

Thứ tự là lộ trình dành cho người tiếp nhận toàn bộ dự án. Người chỉ thực hiện một công việc có thể đọc **01**, **02**, sau đó đi thẳng tới runbook liên quan; ví dụ deploy đọc **15–20**, còn tích hợp ESP32/PLC đọc **09**, **11–15**.

## 2. Cách đọc source theo luồng hoạt động

### 2.1 Khởi động web server

Luồng đọc khuyến nghị:

**Program.cs** → **Configuration/** → **Data/MongoContext.cs** → **Data/MongoDatabaseInitializer.cs** → **Runtime/MongoBootstrapHostedService.cs** → **Components/App.razor** → **Components/Routes.razor**.

Lý do: Program là composition root, nơi cho biết hệ thống có những service nào. Configuration cho biết dữ liệu đầu vào. Mongo bootstrap cho biết dữ liệu nào phải sẵn sàng trước UI và background worker.

### 2.2 Nhận dữ liệu cảm biến

**SystemConfigurationService** tạo socket/sensor mapping → **DynamicMqttConnectionSupervisor** kết nối broker → **SensorMessageBus** tạo ranh giới producer/consumer → **SensorIngestionWorker** xác thực và ghi → **FarmRuntimeState** cập nhật cache → **AlertEngineService**, **AutomationEngineService** và UI tiêu thụ.

Điểm quan trọng: ESP32 không ghi thẳng dashboard. Mọi message phải đi qua định danh socket, SensorId/ChannelId, validation, deduplication và persistence.

### 2.3 Điều khiển thiết bị

UI → **DeviceCommandService** → kiểm tra role, pond scope, commissioning, local override và interlock → **IDeviceCommandTransport** → **Fx5uModbusTcpDeviceTransport** → **ModbusTcpProtocol** → PLC. **DynamicModbusConnectionSupervisor** polling feedback và cập nhật trạng thái.

Điểm quan trọng: command đã ghi không có nghĩa motor đã chạy. Feedback PLC mới là nguồn trạng thái thực.

### 2.4 Commissioning động

UI quản trị → **SystemConfigurationService** → **SystemConfigurationRepository** → desired version → MQTT hoặc Modbus supervisor → node/PLC apply → reported version/ACK → trạng thái Applied.

Quy trình này tồn tại để Admin thay đổi mapping mà không sửa code, đồng thời không nhầm “đã lưu form” với “thiết bị đã áp dụng”.

### 2.5 Nghiệp vụ trại

UI vụ nuôi/kho/sức khỏe → **ProductionCycleService** hoặc **FarmOperationsService** → **FarmRepository** → MongoDB → **DashboardAnalyticsService** tổng hợp cho dashboard.

## 4. Các file ở thư mục gốc

### **Program.cs** và **Program.md**

**Program.cs** là composition root. File nạp JSON/environment, đăng ký Options validator, MongoDB, repository, runtime state, authentication, Blazor, health check và background service; sau đó cấu hình middleware và endpoint. Cần file này vì mọi phụ thuộc phải được nối ở một nơi có thể kiểm tra. Sửa lifetime hoặc thứ tự middleware tại đây có thể ảnh hưởng toàn hệ thống. **Program.md** giải thích quyết định startup, quan hệ DI và thứ tự khởi tạo.

### **AquacultureMonitoring.csproj**

Project chính .NET. Nó xác định target framework, package, lock-file restore và thông tin **PublishContainer** như repository/image base. File liên quan **global.json**, **packages.lock.json**, workflow và Compose. Sửa package phải cập nhật lock file và chạy test.

### **AquacultureMonitoring.sln**

Solution gom project ứng dụng và project test để IDE/CLI build thống nhất. Nó không chứa code runtime nhưng là entry point cho lệnh build toàn repository.

### **global.json**

Khóa major/feature band .NET SDK mong muốn. Lý do là SDK khác phiên bản có thể thay hành vi restore, compiler hoặc container publishing.

### **packages.lock.json**

Khóa dependency gián tiếp/trực tiếp của ứng dụng. File được commit để restore lặp lại; không chỉnh tay.

### **appsettings.json**

Cấu hình mặc định không chứa secret production: logging, Mongo options, operational mode, retention, health score và endpoint notification. Biến môi trường có thể override bằng cú pháp dấu gạch dưới kép. Class tương ứng ở **Configuration/AquacultureOptions.cs**.

### **.env.example**

Mẫu biến môi trường cho Compose. Đây là checklist cấu hình chứ không phải secret thật. Sao chép thành **.env** trên server, thay toàn bộ giá trị mẫu và không commit **.env**.

### **compose.yaml**

Stack HTTP LAN đầy đủ gồm MongoDB, Mosquitto, data-protection init và AquaOps. Network tách frontend/backend; volume giữ database, broker và key. File được **deploy-ubuntu.sh** sử dụng.

### **compose.production.yaml**

Override/chế độ dùng container image bất biến từ GHCR thay vì build source. Nó liên kết biến **AQUAOPS_IMAGE** và **AQUAOPS_VERSION** với image do workflow phát hành.

### **compose.hardware.yaml**

Override dành cho kết nối hardware/host LAN khi cần khác cấu hình stack chuẩn. Đọc cùng **11.OPERATING-MODES.md** để không vô tình bật simulation ở production.

### **.gitignore**

Ngăn commit secret, output build, database local và file runtime. File này là lớp phòng ngừa, không thay thế secret scanning.

### **.gitattributes**

Chuẩn hóa line ending và thuộc tính Git giữa Windows/Linux, đặc biệt quan trọng với shell script phải chạy bằng LF trên Ubuntu.

### **README.md**

Trang vào repository: kiến trúc, tính năng, cách chạy nhanh và liên kết tài liệu. README không thay thế runbook chi tiết; nó định tuyến người đọc.

## 5. Tự động hóa GitHub

### **.github/workflows/publish-container.yml**

Workflow restore locked, build, test và dùng .NET SDK PublishContainer đẩy image lên GHCR. Tag SHA tạo release bất biến. Workflow là cổng chất lượng trước deploy; lỗi verify nghĩa server không nên pull tag đó.

### **.github/dependabot.yml**

Yêu cầu Dependabot kiểm tra NuGet và GitHub Actions. PR tự động vẫn phải qua build/test và review tương thích; không merge chỉ vì version mới hơn.

## 7. Configuration và Config

### **Configuration/AquacultureOptions.cs**

Chứa các class Options cho MongoDB, mode, notification, threshold catalog, behavior, health score, seed và authentication. Strongly typed options giúp compiler/service dùng tên trường rõ ràng thay vì đọc chuỗi JSON rải rác.

### **Configuration/ConfigurationValidation.cs**

Các IValidateOptions kiểm tra cấu hình khi startup. Mục đích là fail fast trước khi hệ thống nhận telemetry hoặc lệnh với cấu hình nguy hiểm. Validator liên quan trực tiếp **Program.cs**, **appsettings.json**, **Config/** và biến môi trường.

### **Configuration/DeviceControlOptions.cs**

Cấu hình timeout, retry, pulse/polling của command transport. Các giới hạn này bảo vệ network/PLC nhưng không thay thế interlock vật lý.

### **Configuration/OperationalModeGuard.cs**

Biến mode thành quyết định rõ ràng: nguồn nào được phép chạy, production có yêu cầu phụ thuộc gì. Nó ngăn simulation vô tình hoạt động trong deployment thật.

### Các file trong **Config/**

| File | Mục đích và lưu ý |
|---|---|
| **authentication.json** | Bootstrap account cho local/khởi tạo; mật khẩu production phải override/đổi và hash được lưu trong MongoDB. |
| **authentication.md** | Giải thích luồng bootstrap, hash và cách tránh lưu credential thật. |
| **sensor-thresholds.json** | Catalog tên/unit/decimal/default threshold theo metric; valid min/max vật lý thuộc firmware. |
| **system-behavior.json** | Retention, timeout offline, health score và tham số hành vi không bí mật. |
| **seed-data.json** | Dữ liệu nền lần đầu: một ao, không tạo sẵn sensor/device. |
| **README.md** | Bản đồ precedence và hướng dẫn thay đổi Config an toàn. |

## 8. Models: ngôn ngữ dữ liệu chung

### **Models/AquacultureModels.cs**

Document/DTO cốt lõi: Pond, SensorDefinition, SensorReading, Device, DeviceCommand, Alert, FeedLog, calibration, maintenance, audit, user và production cycle. File lớn vì chứa vocabulary nền được dùng xuyên layer; tài liệu **AquacultureModels.md** phân nhóm để tránh nhầm document với request DTO.

### **Models/SystemConfigurationModels.cs**

Model commissioning: broker profile, NodeSocket, MQTT/Modbus settings, capability, deployment, connection log, sensor health, installation, quarantine và automation policy. Đây là contract nối trang System Settings với supervisor.

### **Models/FarmOperationsModels.cs**

Kho, giao dịch kho, aquatic health, biosecurity, work order, expense, harvest lot và snapshot nghiệp vụ.

### **Models/DashboardModels.cs**

View model đã tổng hợp dành cho UI. Không nên ghi ngược các object này xuống MongoDB vì chúng là kết quả tính toán.

### **Models/AuthAndProductionModels.md**

Tài liệu phân nhóm các class authentication/production vốn hiện nằm trong AquacultureModels.cs; tồn tại để người đọc nghiệp vụ không phải đọc toàn bộ file model lớn.

## 9. Data, Runtime và Infrastructure

### Data

| File | Mục đích, lý do và quan hệ |

# Phần riêng: kiến thức về các đuôi file trong repository

Phần này giải thích chức năng của định dạng file, tách khỏi bản đồ nội dung phía trên theo yêu cầu bàn giao.

## **.cs** — C# source

Chứa class, record, interface và logic chạy trên .NET. Compiler biến .cs thành assembly. Trong AquaOps:

- Models định nghĩa dữ liệu.
- Services chứa use case/quy tắc.
- Data chứa MongoDB access.
- Sensors/Devices chứa protocol và worker.
- Program.cs nối toàn hệ thống.

Không lưu secret trong hằng số .cs. Comment nên giải thích “vì sao” và invariant, không lặp lại cú pháp.

## **.razor** — Blazor Razor component

Kết hợp markup HTML, directive và C#. File có @page là route; file không @page thường là component tái sử dụng. Logic nghiệp vụ quan trọng phải gọi service vì kiểm tra chỉ ở UI có thể bị bỏ qua.

## **.md** — Markdown documentation

Văn bản tài liệu dùng heading, list, table và link. Markdown được GitHub render nhưng vẫn đọc được dạng text. Companion .md mô tả source cùng tên; Docs chứa kiến trúc/runbook/hồ sơ quyết định.

## **.json** — JSON data/configuration

Dữ liệu key/value có cấu trúc. AquaOps dùng cho appsettings, catalog, seed, example payload, lock file và launch profile. JSON không cho comment chuẩn; giải thích field phải đặt trong .md hoặc class options.

## **.yaml / .yml** — YAML configuration

Định dạng cấu hình phân cấp, nhạy với thụt lề. Compose và GitHub Actions dùng YAML. Chuỗi có ký tự đặc biệt nên quote rõ. Không commit secret thật vào YAML.

## **.csproj** — MSBuild project

XML mô tả target framework, package reference, project reference, content và container publishing. Sửa file này có thể thay dependency/build output; luôn restore locked và test.

## **.sln** — .NET solution

File solution gom nhiều project và cấu hình build. IDE và dotnet build dùng nó để build ứng dụng cùng tests.

## **packages.lock.json** — NuGet lock file

JSON đặc biệt do NuGet sinh để khóa dependency graph. Không chỉnh tay; cập nhật bằng restore hợp lệ và review diff.

## **.sh** — POSIX/Bash shell script

Script Linux/Ubuntu/container init. Cần line ending LF, executable bit và shell phù hợp. Quote biến, kiểm tra path trước thao tác destructive và dùng set options có chủ đích.

## **.ps1** — PowerShell script

Script Windows/cross-platform PowerShell. Nên dùng LiteralPath với đường dẫn người dùng, ErrorAction Stop và không ghép command phá hủy từ chuỗi chưa kiểm tra.

## **.c** — C source cho ESP-IDF

Firmware chạy trên ESP32, quản lý FreeRTOS task, Wi-Fi, MQTT, socket, NVS và GPIO/protocol. C yêu cầu quản lý buffer/length cẩn thận; lỗi có thể crash edge hoặc gây sai điều khiển.

## **.h** — C header

Khai báo API, type, constant public giữa ESP-IDF component. Header là contract compile-time; thay struct cần xem compatibility của mọi project include.

## **CMakeLists.txt** — CMake build descriptor

Khai báo project/component và source/include dependency cho ESP-IDF. Tên file không có đuôi nhưng có cú pháp CMake.

## **Kconfig.projbuild** — ESP-IDF menu configuration

Định nghĩa option hiện trong menuconfig. Phù hợp với bootstrap/build-time defaults, không phù hợp cho cấu hình nghiệp vụ cần Admin đổi động.

## **sdkconfig.defaults** — mặc định ESP-IDF

Giá trị cấu hình nền khi tạo sdkconfig. File **sdkconfig** thực tế có thể phụ thuộc máy và thường không commit; defaults phải không chứa Wi-Fi/MQTT secret production.

## **.csv** — comma-separated values

Trong firmware, **partitions.csv** mô tả bảng phân vùng flash chứ không phải dữ liệu báo cáo. Sai offset/size có thể làm firmware không boot hoặc thiếu vùng NVS.

## **.conf** — service configuration

Text config cho Mosquitto. Directive quyết định listener, persistence, auth và log. Cần kiểm tra với đúng version broker vì directive có thể thay đổi.

## **.css** — Cascading Style Sheets

Quy định màu, spacing, layout responsive và trạng thái UI. CSS không được dùng làm lớp bảo mật; ẩn nút không đồng nghĩa cấm API/service.

## **.js** — JavaScript

Chạy trong trình duyệt, hỗ trợ chức năng Blazor không có API .NET trực tiếp. Giữ helper nhỏ, validate input và tránh chèn HTML không tin cậy.

## **.svg** — Scalable Vector Graphics

Đồ họa vector dạng XML, dùng làm favicon. SVG co giãn không vỡ hình và có thể được browser cache.

## **.env / .env.example**

Danh sách KEY=VALUE cho Compose. **.env.example** được commit như schema/checklist; **.env** chứa giá trị thật và phải bị ignore. Khoảng trắng, dấu # và ký tự Unicode không quote có thể làm shell/Compose parse sai.

## **.gitignore**

Pattern loại file khỏi Git tracking. Nếu file đã được track trước khi thêm ignore, cần xử lý Git index riêng; ignore không xóa lịch sử đã commit.

## **.gitattributes**

Quy định cách Git xử lý line ending, binary/text và thuộc tính file. Nó giúp shell script giữ LF khi contributor làm việc trên Windows.

## File không có đuôi

Một số file như **Dockerfile** (project này không dùng), **CMakeLists.txt** hoặc executable script có thể không có đuôi. Chức năng được xác định bởi tên, shebang hoặc công cụ đọc file, không chỉ phần mở rộng.

## Nguyên tắc cuối cùng

Đuôi file cho biết công cụ và cú pháp, không cho biết mức độ tin cậy. Luôn xác định thêm:

- file được thực thi ở build time, startup hay runtime;
- nó có chứa secret hoặc dữ liệu bền vững không;
- nguồn nào sinh ra file và có nên chỉnh tay không;
- thay đổi file ảnh hưởng server, browser, container hay firmware;
- bước kiểm tra tương ứng là build, test, compose config, flash firmware hay kiểm tra vận hành.
