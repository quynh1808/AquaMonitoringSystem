# ESP32 bootstrap provisioning

Firmware không chứa SSID, mật khẩu, IP broker, FarmId, PondId hoặc NodeId cụ thể. Bootstrap được
lưu trong namespace NVS `aqua_boot`. Bản hiện tại dùng UART console; có thể thay UI bằng SoftAP/BLE
mà không đổi storage API trong `Firmware/components/aqua_provisioning`.

## Sensor node

Flash firmware, mở serial monitor rồi nhập từng lệnh:

```text
set wifi_ssid TEN_WIFI
set wifi_pass MAT_KHAU_WIFI
set mqtt_uri mqtt://192.168.100.66:1883
set mqtt_user aquaops_gateway
set mqtt_pass MAT_KHAU_MQTT
set farm_id farm_main
set pond_id pond_01
set node_id esp32-sensor-01
status
restart
```

## ESP32 PLC simulator

```text
set wifi_ssid TEN_WIFI
set wifi_pass MAT_KHAU_WIFI
set node_id fx5u-sim-01
status
restart
```

Console không echo giá trị secret. Khi triển khai thật nên bật NVS encryption và secure boot/flash
encryption theo chính sách thiết bị. Không commit `sdkconfig` chứa secret.

## Build bằng PlatformIO trên Windows

Đây là cách khuyến nghị cho `esp32_sensor_node`:

~~~powershell
cd Firmware/esp32_sensor_node
pio run -t clean
pio run -e aquaops_sensor_node
pio device list
pio run -e aquaops_sensor_node -t upload --upload-port COM5
pio device monitor -p COM5 -b 115200
~~~

Thay `COM5` bằng port thật. Lần build đầu cần Internet để PlatformIO tải toolchain/ESP-IDF. Không
cần cài ESP-IDF riêng khi PlatformIO hoạt động.

Tài liệu đầy đủ:

- [Kiến trúc PlatformIO](../Firmware/PLATFORMIO.md).
- [Runbook build, flash và commissioning](../Firmware/esp32_sensor_node/PLATFORMIO-RUNBOOK.md).
- [Xử lý lỗi PlatformIO, USB, Wi-Fi, MQTT và sync](../Firmware/esp32_sensor_node/PLATFORMIO-TROUBLESHOOTING.md).

## Build bằng ESP-IDF CLI

```powershell
cd Firmware\esp32_sensor_node
idf.py set-target esp32
idf.py build
idf.py -p COM5 flash monitor
```

PLC simulator thực hiện tương tự trong `Firmware\esp32_fx5u_plc_simulator`.

PlatformIO hiện mới được cấu hình và kiểm chứng cho sensor node; không dùng environment sensor node
để build PLC simulator.

### Vì sao thành phần hoặc quy trình này cần tồn tại

### Vai trò trong toàn hệ thống

Là knowledge base về kiến trúc, triển khai, vận hành, bảo mật, hardware và lịch sử milestone.

Tài liệu phải nêu mục tiêu, prerequisite, lý do từng bước, kết quả mong đợi, cách xác minh, rollback và liên kết tới source có thẩm quyền.

### Cách đọc và sử dụng tài liệu này

1. Đọc phần mục đích để biết đầu ra mong đợi.
2. Mở file source hoặc cấu hình được liệt kê ở phần triển khai.
3. Theo quan hệ upstream để biết dữ liệu đến từ đâu và downstream để biết thay đổi ảnh hưởng ai.
4. Xem failure mode, authorization, idempotency và trạng thái no-data/offline trước khi sửa happy path.
5. Cập nhật tài liệu trong cùng commit với source để tránh kiến thức bị lỗi thời.
